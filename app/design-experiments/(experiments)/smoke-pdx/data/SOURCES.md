# Smoke PDX — data provenance

`smoke.json` is generated by `_build.py` (re-run: `python3 _build.py`).
Snapshot taken 2026-08-11T05:11Z. Every layer drawn was fetched and counted.
**No API keys are used anywhere in this experiment.**

## Tier key

- **A** — primary. The agency that owns the data, publishing it directly.
- **B** — aggregator or model republishing/deriving from government data.
- **C** — community or crowdsourced.
- **D** — could not fetch, could not verify, or provenance unclear.

## 1. Air monitors — EPA AirNow — Tier A

- **Endpoints:** `https://files.airnowtech.org/airnow/today/monitoring_site_locations.dat`
  and `https://files.airnowtech.org/airnow/today/HourlyData_YYYYMMDDHH.dat`
- **Publisher:** US EPA AirNow, carrying monitors operated by **Oregon DEQ** and
  the **Washington Department of Ecology**
- **Cadence:** hourly
- **API key:** none. These are plain pipe-delimited files, no signup.
- **Verified:** 2026-08-10, **373** PM2.5 sites inside the region (22 of them in
  the metro box), **21** of the last 24 hourly files usable, **151** sites with a
  valid NowCast
- **Join:** site file carries a 12-digit AQSID, hourly file a 9-digit one. Join
  on the last 9 characters.
- **Fields used:** `PM2.5` concentration (µg/m³), site name, agency, lat/lon (WGS84)

### AQI is NowCast, not the raw hourly value

This is the detail most reimplementations get wrong. AirNow's published AQI runs
the last 12 hours through a decay-weighted average (**NowCast**) before hitting
the breakpoint table. Taking one raw hourly reading, running it through the
**24-hour** breakpoints, and calling the result "AQI" would produce a number that
disagrees with every other source in town.

So `_build.py` fetches 12 hourly files and computes NowCast properly:

- `w = max(1 - (max - min) / max, 0.5)`, then `Σ(wⁱ · cᵢ) / Σ(wⁱ)`, newest first
- EPA's validity rule is honored: **2 of the 3 most recent hours** must be
  present, or the site reports no value

### Two timing bugs that silently blanked the whole map

Both were caught only because a rebuild dropped from 7 reporting monitors to 0.
Worth knowing before reimplementing this against any hourly feed.

**1. The newest file is often half-written.** AirNow publishes progressively, so
the file for the most recent hour frequently exists while containing ~113 PM2.5
rows against a complete file's ~1,350. Anchoring the 12-hour window to it left
the newest slots nearly empty and failed the 2-of-3 rule for every station in the
country. The script now row-counts each file and rejects anything under 800 rows,
then anchors on the newest hour that passes.

**2. A missing file is not a silent monitor.** On 2026-08-10 the 00Z, 01Z, and
02Z files were absent entirely. Evaluating "2 of the 3 most recent hours" over
*clock* hours therefore marked every station invalid, when the gap was in AirNow's
publishing and not in the monitors. The rule is now evaluated over the three most
recent hours **we could actually read**, while NowCast's decay weights still use
true hour offsets so the time math stays correct.

Breakpoints are the PM2.5 table **as revised in the 2024 NAAQS update** (Good now
tops out at 9.0 µg/m³, not 12.0).

**What the source does not have:** no per-site AQI, no forecast, and no
uncertainty estimate. We compute AQI ourselves and show the NowCast
concentration next to it so the arithmetic is auditable.

**Monitors with no reading are not drawn, but they are counted.** 222 of 373 sites
had no valid NowCast at snapshot time. Drawing them was tried and reverted: 222
blank markers are noise that competes with the readings, and they crowded the
dense parts of the network. The honesty requirement is met by stating the ratio
plainly ("151 of 373 monitors are reporting; the quiet ones are not drawn") in
the legend and again under the map, so the coverage of the network is never
overstated even though the silent stations are absent.

**Readings are drawn as soft radial blooms, without their numbers.** Hue, radius, and falloff all climb
with AQI, so the field is scannable across 151 stations at a glance, which 151
two-digit labels are not, and overlapping blooms pool into an approximate field
rather than stacking as discrete pins. The exact value is one click away, and the legend
carries the scale. Stale readings (an older value, when no current NowCast
exists) stay hollow with a dashed ring so they can never pass for live.

**Badges thin out when zoomed out, keeping the HIGHEST reading per grid cell.**
Dense networks around Puget Sound and Spokane otherwise stack into an unreadable
pile. Thinning toward the worst value is the only safe direction for air quality:
hiding a 209 behind a 12 would be the dangerous kind of decluttering.

**We tried to find them an older reading, and there isn't one.** The build script
pulls 24 hours (the first 12 feed NowCast, the rest exist purely to answer "when
did this station last say anything") and falls back to the most recent single
reading, labeled "last reading" with its age and drawn in a dashed, washed style
so it can never pass for live. On 2026-08-10 that fallback found **nothing**: a
separate probe walked the dated archive back a full **72 hours** and none of the
15 had reported PM2.5 at any hour. They are quiet at the source, not missed by our
window. The fallback code stays because it will earn its keep on an intermittent
station or a different region.

Worth noting for anyone extending this: 9 of the 15 are marked `Active` in
AirNow's own site file, so that status field is not a reliable indicator of
whether a station is currently producing PM2.5.

## 2. Wind — Open-Meteo — Tier B

- **Endpoint:** `https://api.open-meteo.com/v1/forecast`
- **Cadence:** hourly
- **API key:** none for non-commercial use, no signup
- **Verified:** 2026-08-10, **651** grid cells returned
- **Fields used:** `wind_speed_10m` (mph), `wind_direction_10m` (degrees)

**Tier B and not A because this is model output, not station observation.**
Open-Meteo derives from national weather models rather than owning instruments.

The Tier A alternative is NOAA's `api.weather.gov`, also keyless, which returns
real station observations (KPDX read 320° at 16.7 km/h gusting 29.6 when we
checked). We chose the model because stations are scattered and uneven, while an
even grid is what makes arrows read as a flow field. **The tradeoff is stated
here rather than hidden**, and swapping to NWS would mean changing one function
in `_build.py`.

**Grid:** two densities, 0.45° across the region and 0.08° across the metro. The
map draws the fine grid at zoom ≥ 9 and the coarse grid below it, so the pattern
stays legible at both scales. Arrows fade out within 1.2° of the region edge, so
the grid ends softly instead of drawing a rectangle over the map.

**Direction convention:** meteorology names the direction wind comes **from**.
The map rotates arrows 180° so they point where the smoke is **going**, and the
legend says so.

**Arrows are drawn on a screen-space lattice, not on the data grid.** Because the
data has two densities, rendering cells directly made the fine metro patch read as
a dense square floating inside a sparse field. The map now samples the nearest
cell onto an even lattice spaced ~88px apart, snapped to a global grid so arrows
do not shimmer while panning, and re-samples on every pan and zoom. Apparent
spacing is then identical at every zoom.

## 3. Fire perimeters — NIFC WFIGS — Tier A

- **Endpoint:** `https://services3.arcgis.com/T4QMspbfLg3qTGWY/arcgis/rest/services/WFIGS_Interagency_Perimeters_Current/FeatureServer/0`
- **Publisher:** National Interagency Fire Center
- **Cadence:** continuous
- **API key:** none
- **Verified:** 2026-08-10, **118** perimeters intersecting the region. Largest:
  Big Grass at 553,972 acres, 35% contained.
- **Fields used:** `poly_IncidentName`, `poly_GISAcres`, `attr_PercentContained`

**Transformation:** geometry generalized server-side with
`maxAllowableOffset=0.004` (degrees). Full-resolution perimeters carry far more
vertices than this zoom can render and would bloat the repo. No attribute is
altered.

**Rate limits are real.** The public service returned HTTP 429 twice during the
source hunt. `_build.py` should be re-run rather than retried in a tight loop.

**Containment is sometimes null**, and the popup omits the row entirely in that
case. Showing `0%` would read as "not contained at all," which is a different
claim than "not reported."

## Considered and rejected

**NASA FIRMS VIIRS hotspots** (Tier A, keyless, verified: 3,297 detections in
Oregon and 6,711 across the Pacific Northwest in 24 hours). Dropped on purpose.
A VIIRS detection means a satellite saw heat in a roughly 375m cell, which
includes agricultural burns, industrial flares, and hot roofs. Two of the
detections sat inside the Portland metro and neither was a wildfire. Named
perimeters carry meaning a reader can trust; 3,297 ambiguous dots invite a wrong
conclusion. Endpoint recorded in the skill's `known-sources.md` if we want it later.

**OpenAQ v3** and **PurpleAir**: both require API keys. PurpleAir would add real
spatial density from citizen sensors, but it is Tier C and its readings need a
correction factor during smoke events.

**Open-Meteo air-quality endpoint** (keyless): returned PM2.5 4.6 and US AQI 38
downtown, which independently corroborates the AirNow monitor at SE Lafayette
reading 4.9. Not drawn, but a useful cross-check, and it is the obvious source if
we ever want a forecast layer.

## The color pools are a visual aid, not a model

Soft translucent blooms are drawn around each reporting monitor and accumulate
where monitors cluster, which makes the smoke read as a field rather than as
isolated dots. **They are not an interpolated or modeled surface**, and nothing
should be read off them between monitors. The page says so under the map, because
a smooth wash is persuasive and easy to mistake for a model.

If a genuine surface is ever wanted, Open-Meteo's keyless air-quality endpoint
already returns modeled PM2.5 for any coordinate and would be the honest way to
build one, drawn as Tier B and labeled.

## A note on what this snapshot shows

At snapshot time Portland was **clean** (AQI 12 to 32, all "Good") while 118 fires
burned across the region and monitors 200 miles east read **209, "Very
Unhealthy"**. That contrast is the whole point of the map, and the wind layer is
what explains it.

Widening the monitor net from the metro to the full region also retired an earlier
caveat: the upper bands of the AQI ramp are no longer untested. Good through Very
Unhealthy all render against live data in this snapshot. Only Hazardous (301+)
remains unexercised.

## Live path

`app/api/smoke-pdx/route.ts` refreshes monitors and the **metro** wind cells
every 15 minutes,
reusing the exact NowCast and AQI logic from `_build.py`. Perimeters come from
this snapshot rather than being refetched, since they move on the order of days.

The route exists despite every source being keyless, for two reasons: AirNow's
file server sends no CORS headers, so the browser cannot read it directly; and
server-side caching keeps one public file host from being hit once per visitor.
On any failure the route serves this snapshot with `live: false`, and the legend
labels it "saved copy."
